# Qulogi

[Русский](README.md) | [English](README.en.md)

Qulogi — кроссплатформенный инструмент для свободного доступа в интернет при активной фильтрации трафика. Три способа обхода в одном ядре: обфусцированный туннель до собственного сервера, маскировка туннеля под разрешённые сервисы и локальный DPI-обход на уровне TLS. Ядро написано на Go, интерфейс — Flutter с Material 3 Expressive. Никаких чужих серверов посередине: трафик идёт только через то, что настроили вы.

Статус: ядро, консольные клиенты и десктопный путь полностью рабочие. Android-режим VPN (VpnService + gVisor netstack), TLS-камуфляж и DPI-стратегии в духе zapret реализованы; iOS — каркас NetworkExtension (см. дорожную карту).

## Как это работает

### Режим VPN (Android, полный туннель)

Приложение поднимает Android VpnService, пакетный дескриптор передаётся в Go-ядро, где gVisor netstack терминирует TCP и UDP и направляет потоки в движок — через туннель или напрямую с DPI-трюками. Kill switch удерживает интерфейс поднятым и блокирует весь трафик, когда защита выключается, — утечек нет. DNS в туннельном режиме идёт по TCP (RFC 7766), поэтому утечки через UDP нет.

```text
приложения устройства
      |
      v
Android VpnService (TUN fd)
      |
      v
gVisor netstack (internal/vpn) -- TCP/UDP потоки
      |
      +-- egress tunnel --> AES-256-GCM + камуфляж --> qulogid (VPS) --> интернет
      +-- egress direct --> TLS-сплиты в духе zapret -> напрямую
```

### Режимы SOCKS5-прокси (десктоп и Android)

- **Туннель.** Весь трафик уходит в зашифрованном туннеле на ваш сервер и выходит в интернет уже с него.
- **Туннель + камуфляж.** Поверх туннеля — TLS-образная рамка: клиент посылает правдоподобный ClientHello с SNI разрешённой платформы (`vkvideo.ru`, `rutube.ru`, …), сервер отвечает фиктивным ServerHello, дальше данные идут внутри application-data записей. Для инспекции это выглядит как HTTPS к видеохостингу, хотя под обёрткой — наш GCM-поток.
- **DPI.** Трафик идёт напрямую, но ClientHello разбивается так, чтобы инспекция не увидела имя хоста в первом пакете. Сервер не нужен.

## Что внутри

- `internal/tunnel` — протокол туннеля: рукопожатие со свежими солениями, HKDF-SHA256, AES-256-GCM, кадры со счётчиком. Неверный ключ отбрасывается на первом же кадре.
- `internal/transport` — TLS-камуфляж: генератор ClientHello с настраиваемым SNI (браузерный набор шифров, GREASE, key share, паддинг до ~517 байт), фиктивный полёт ServerHello+CCS, автоопределение режима на сервере. Это «транспорт через разрешённые сервисы»: соединение маскируется под трафик whitelisted-платформы.
- `internal/dpi` — стратегии разрыва ClientHello в духе zapret/goodbye-dpi: авто после SNI, первый байт, 8/32 байта, multi-split (дополнительные разрывы внутри хостнейма против сборщиков сегментов), опциональная пауза между сегментами. Все трюки прозрачны для сервера и не требуют прав.
- `internal/vpn` — userspace TCP/IP-стек на gVisor netstack поверх TUN: перехват TCP (forwarder) и UDP, DNS-over-TCP через туннель, kill switch (SetBlocked), счётчики трафика.
- `internal/socks5` — локальный SOCKS5-сервер с подключаемым «насосом» трафика.
- `internal/engine` — режимы, защитная маршрутизация сокетов (protect), счётчики, статус.
- `cmd/qulogi` — клиентская консоль, `cmd/qulogid` — серверная.
- `mobile` — биндинги gomobile: SOCKS5-движок и VPN-движок (`ConfigureVPN`/`StartVPN(fd, mtu)`/`StopVPN`/`SetBlocked`), интерфейсы `Protector` и `LogSink`.
- `app` — Flutter-клиент: режимы VPN/Туннель/DPI, настройки маскировки, автозапуск и kill switch, журнал.
- `app/android` — `QulogiVpnService` (foreground, specialUse), `BootReceiver` (автозапуск, по умолчанию выключен), kill switch в приложении.
- `ios` — каркас NetworkExtension (экспериментально).

## Быстрый старт

### Сервер

На любой VPS с Linux:

```bash
go install github.com/mel0k1/qulogi/cmd/qulogid@latest
qulogid -listen :443 -psk ДЛИННЫЙ_СЛУЧАЙНЫЙ_КЛЮЧ
```

Откройте выбранный порт (TCP) в брандмауэре. Сервер сам понимает и камуфляжные, и «прозрачные» соединения — отдельных настроек не нужно. PSK — единственная защита входа, делайте его длинным и храните как пароль.

### Клиент (консоль)

```bash
go install github.com/mel0k1/qulogi/cmd/qulogi@latest
qulogi -server example.com:443 -psk ТОТ_ЖЕ_КЛЮЧ -camo -fake-ch -sni vkvideo.ru
```

На `127.0.0.1:1080` появится SOCKS5. Флаги `-camo`, `-fake-ch`, `-sni` включают маскировку под разрешённый домен; без них туннель работает в исходном формате.

Без `-server` клиент работает в режиме DPI: `qulogi -split 0 -multi`, где 0 — автоподбор точки разрыва после SNI, `-multi` — дополнительные разрывы.

### Приложение

```bash
git clone https://github.com/mel0k1/Qulogi.git
cd Qulogi/app
flutter pub get
flutter run
```

На Android: выберите режим **VPN**, укажите сервер и ключ, нажмите кнопку — система спросит разрешение на VPN. В настройках доступны маскировка (TLS-камуфляж + SNI), автозапуск (выключен по умолчанию) и kill switch. Для жёсткой защиты дополнительно включите в системе «Always-on VPN» и «Блокировать соединения без VPN».

На десктопе приложение запускает бинарник `qulogi` из PATH; режим VPN там недоступен — используйте SOCKS5.

## Сборка из исходников

Ядро:

```bash
go build ./cmd/qulogi ./cmd/qulogid
```

Биндинги для Android-приложения:

```bash
go install golang.org/x/mobile/cmd/gomobile@latest
go install golang.org/x/mobile/cmd/gobind@latest
gomobile init
gomobile bind -target=android -androidapi 29 \
  -abi arm64-v8a,armeabi-v7a,x86_64 \
  -o app/android/app/libs/mobile.aar ./mobile
```

Готовые бинарники и APK собирает CI во вкладке Actions.

## Безопасность

- Ключ выводится из PSK через HKDF-SHA256 со свежими солениями на каждое соединение; соления никогда не повторяются.
- Каждый кадр шифруется AES-256-GCM со своим nonce, счётчик кадра входит в AAD — повтор и подмена отсекаются.
- Неверный PSK не раскрывает ничего: соединение молча закрывается на первом кадре.
- Камуфляж — это обёртка, а не защита: криптографию несёт GCM-слой, TLS-заголовки лишь имитируют форму трафика.
- Kill switch: после выключения VPN-интерфейс остаётся поднятым и новые связи отклоняются — ни один пакет не уходит мимо туннеля.
- Журнал по умолчанию выключен; флаг `-v` показывает только события соединений, без содержимого трафика.

## Ограничения

- В режиме «туннель» через VPN транзитируется только TCP; UDP (кроме DNS по TCP) отбрасывается — QUIC-клиенты автоматически возвращаются к TCP. В режиме «direct» UDP проходит как есть.
- Камуфляж SNI помогает против SNI-фильтрации; если адрес сервера заблокирован по IP, поможет только другой адрес/порт или CDN-фронтинг (в роадмапе).
- Трюки разрыва ClientHello эффективны не на всех провайдерах: DPI постоянно эволюционирует, подбирайте стратегию под свою сеть.
