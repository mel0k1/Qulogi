# Автопоиск транспорта (Relay Discovery)

Статус: **M1–M3 реализованы** (`internal/discover`, вкладка «Релеи» в приложении, `qulogicat`, транспорт `storage-webdav`); умный сплит со SNI-sniffing в TUN-стеке реализован (`internal/route`, `internal/vpn`). Дальше — дорожная карта M4–M5.

## Проблема

В классической схеме нужен свой сервер за пределами фильтруемой сети:

```text
Классический VPN:   устройство ──► VPS ──────────────────► интернет
                                 (IP пал, SNI виден)

Qulogi сейчас:      устройство ──► VPS ──────────────────► интернет
                                 (камуфляж под vkvideo.ru и т.п.)

Цель автопоиска:    устройство ──► белая платформа ──────► интернет
                    (пакеты живут внутри разрешённого трафика, VPS не нужен)
```

Камуфляж решает проблему «SNI виден», но не решает «IP релея забанен» и «нет своего VPS». Автопоиск закрывает обе: клиент сам находит работающий транзит — будь то релей сообщества, CDN разрешённой платформы или её облачное хранилище.

## Классы транспортов (реестр адаптеров)

| Тип | Схема | Задержка | Нужен VPS | Статус |
|-----|-------|----------|-----------|--------|
| `qulogi-tls` | свой релей `qulogid` с камуфляжем | низкая | да | работает |
| `qulogi-tcp` | свой релей без обёртки | низкая | да | работает |
| `cdn-front` | край белого CDN проксирует на релей за тем же CDN | низкая | да, но IP CDN | план M4 |
| `storage-webdav` | кадры туннеля как файлы/чанки в белом облаке | секунды | нет | работает |
| `bot-longpoll` | long-poll/bot API белых платформ | секунды | нет | план M5 |
| `turn-relay` | открытые TURN-релеи белых сервисов | низкая | нет | разведка |

Примечания по классам:

- **`cdn-front`.** Клиент соединяется с краем CDN по разрешённому SNI, а внутри HTTP-запросов указывает Host релея, припаркованного за тем же CDN. Работает, только если CDN не сверяет SNI с Host. Кандидаты — белые CDN: Yandex Cloud CDN, NGENIX, VK-инфраструктура.
- **`storage-webdav`** (реализован в M3, `internal/webdav`). Самый честный путь «устройство → Яндекс → интернет» без VPS: кадры GCM-потока кладутся файлами-чанками (по умолчанию 256 КиБ) в каталог-почтовый ящик `<mailbox>/<session>/up` и забираются из `…/down`. Обе стороны говорят с облаком обычный HTTPS, адрес релея не виден вовсе. Релей следит за базовым каталогом (`PROPFIND`, опрос 2 с) и обслуживает каждую сессию `s-<hex>`; отработанные сессии удаляются. Типичная задержка — 2–4 с (мультисплит-опрос) — годится для веб-сёрфинга, RSS, почты; не для звонков. Клиент: `qulogi -dav https://webdav.yandex.ru -dav-user … -dav-pass … -dav-mailbox qulogi -psk …`; релей: `qulogid -listen "" -dav … -dav-mailbox qulogi -psk …`.
- **`bot-longpoll`.** Официальные API белых платформ (боты, лонг-поллинг) дают двусторонний канал, но переносят JSON-обёртки: минус скорость, плюс — никакой аномалии в трафике.
- **`turn-relay`.** WebRTC-релеи белых сервисов иногда доступны как открытые релеи; при обнаружении это идеал: низкая задержка и полностью разрешённый адрес. Требует регулярного сканирования.

## Каталог релеев (формат v1)

Каталог — подписанный JSON. Публикуется на нескольких зеркалах: обычный HTTPS, DNS TXT (фрагментами), белые облачные хранилища, QR/ссылки-инвайты. Клиент пытается все зеркала параллельно и берёт первое, чья подпись сходится с пиновым ключом. Последний хороший каталог кэшируется локально и выручает, когда все зеркала недоступны.

### Зеркала

| Тип | Как выглядит | Заметки |
|-----|--------------|---------|
| `https` | `{"type":"https","url":"https://…/catalog.json"}` | GitHub raw, jsDelivr, любые статические хостинги |
| `dns-txt` | `{"type":"dns-txt","name":"_qulogi.example.org","server":"77.88.8.8:53"}` | собственный DNS-клиент поверх UDP — работает без системного резолвера; HTTPS по указателю из TXT, если запись не влезает |
| `doh` | `{"type":"doh","name":"_qulogi.example.org","url":"https://dns.google/dns-query"}` | RFC 8484, wire-format POST |

Официальный community-каталог живёт в [mel0k1/qulogi-catalog](https://github.com/mel0k1/qulogi-catalog): оба HTTPS-зеркала из таблицы указывают на него, PR с релеями подписываются сопровождающими, CI репозитория проверяет подпись на каждый PR. Публичный ключ (`discover.CommunityPubKeyB64`) зашит в клиентов: каталог без верной подписи отвергается — compromised-зеркало может подсунуть только более старый, всё ещё подписанный список.

TXT-_payload: либо одна строка `https://…` — указатель на HTTPS-каталог, либо base64 каталога, нарезанный на строки по 200 символов с двузначным шестнадцатеричным префиксом порядка (`00…`, `01…`). Клиент собирает строки, сортирует по префиксу и декодирует.

```json
{
  "version": 1,
  "updated": "2026-10-26T12:00:00Z",
  "ttl_min": 120,
  "key_id": "qulogi-dir-2026q4",
  "relays": [
    {
      "id": "owl-eu-1",
      "region": "eu-central",
      "weight": 60,
      "transports": [
        { "type": "qulogi-tls", "addr": "r1.example.net:443", "sni": "vkvideo.ru", "fp": "b3x9…" },
        { "type": "cdn-front",  "addr": "https://r1.example.net/edge", "sni": "cdn.whitelisted.ru" }
      ]
    }
  ],
  "sig": "…base64 Ed25519…"
}
```

Подпись накрывает канонический JSON без поля `sig` (реализация: `discover.Directory.Sign/Verify`). Свежесть ограничивается `ttl_min` — устаревший каталог отбрасывается даже с верной подписью.

## Пайплайн клиента

1. **Bootstrap.** Хоть одно зеркало каталога должно быть достижимо: список зеркал зашит в сборку + кэш последнего рабочего зеркала локально.
2. **Верификация.** Ed25519 по пиновому ключу, TTL, структурная валидация.
3. **Пробник.** Параллельный TCP-dial до каждого транспорта (16 горутин, общий бюджет), RTT как первичная метрика.
4. **Выбор.** Сортировка по `RTT × (1 − weight/200)` — операторская подсказка дисциплинирует, но не перекрывает факты.
5. **Подключение** к лучшему, остальные — в тёплый резерв.
6. **Health-check** раз в N секунд; деградация → автоматический переезд на следующий кандидат без участия пользователя.

Всё это уже работает на уровне каталога: `discover.Pick(ctx, dir, n, budget, probe)`.

## Приватные релеи и инвайты

Публичный каталог — для сообщества; личные релеи распространяются ссылками вида:

```text
qulogi://relay/owl-eu-1?type=qulogi-tls&addr=r1.example.net%3A443&sni=vkvideo.ru&psk=…
qulogi://catalog/?url=https%3A%2F%2Fmirror.example%2Fcatalog.json&name=Community
```

`psk` в ссылке обязателен для qulogi-транспортов (клиент должен аутентифицироваться на qulogid), поэтому инвайт — это секрет: распространяйте его как пароль. В приложении ссылка импортируется тремя путями: вставить текст, отсканировать QR, открыть deep link `qulogi://` — Android ловит схему и передаёт её в приложение. Любой релей можно отправить обратно QR-кодом с вкладки «Релеи».

Каталоги подписываются утилитой оператора `qulogicat` (`-gen` → ключи, `-in relays.json -out catalog.json` → подписанный каталог, `-txt` → строки для DNS-зоны):

```bash
qulogicat -gen
qulogicat -key <seed> -in relays.json -out catalog.json -ttl 120 -key-id qulogi-dir-2026q4
qulogicat -key <seed> -in relays.json -txt        # куски base64 для TXT
qulogicat -txt -url https://mirror.example/catalog.json   # или указатель
```

## Умный сплит (реализован, важно для мобильных)

В whitelist-режиме туннелировать всё — расточительно и палевно. Клиент держит локальную таблицу маршрутов (`internal/route`):

- разрешённый трафик пускает напрямую (быстро, без нагрузки на релей);
- остальное — через туннель или best-транспорт из каталога;
- правило «всегда через релей» перекрывает белый список; пользовательские правила перекрывают встроенные.

Встроенный стартовый список — Яндекс, VK/Mail.ru, банки, госсервисы, маркетплейсы, крупные операторы плюс основные сети этих платформ. В SOCKS-режиме сплит работает по домену назначения. В VPN-режиме TUN-стек подглядывает SNI: первые байты каждого TCP-потока буферизуются (`internal/vpn/sniff`), из ClientHello извлекается hostname (`transport.ParseClientHello`), и решение direct/tunnel принимается уже по домену; не-TLS и «молчаливые» потоки (SSH, SMTP) не страдают — окно подглядывания 1 с, дальше поток идёт по IP-политике. DNS в split-режиме ходит по TCP внутри туннеля (защита от подмены ответов), прочий не-белый UDP отбрасывается — QUIC-клиенты возвращаются к TCP, который уже маршрутизируется по правилам.

Это экономит батарею и трафик релея и делает образ трафика естественнее: типичные для пользователя белые сервисы ходят как ходили.

## Риски и границы

- **ToS платформ.** Storage/bot-транспорты используют API не по назначению: возможны блокировки аккаунтов-ретрансляторов. Релеи должны быть одноразовыми и взаимозаменяемыми.
- **Задержки.** Storage-класс — секунды; подходит не под все задачи, приложение должно честно показывать класс транспорта.
- **Хрупкость cdn-front.** CDN может начать сверять SNI/Host в любой момент — поэтому транспортов в каталоге несколько, и выбор автоматический.
- **Юридическое.** Проект для восстановления доступа к информации; использование API сторонних сервисов — на страх и ответственность оператора релея.
